## THE ONE-PARAGRAPH MISSION

Cabin is a macOS + iPadOS app that turns your seat into a window seat. It
recreates the full sensory experience of flying on a Boeing 787-9 in a
first-class cabin — photorealistic 3D window views (day, dusk, night,
weather, aurora, cities, storms), a living 3D cabin you can look around in,
an inflight-entertainment system with live TV channels, films, music, games,
a flight map, meals, and a fully featured work mode (focus sessions,
pomodoro, wellness reminders, force breaks) — all rendered locally with
Metal on the devices you already own, offline-first, privacy-first, and
monetized at $20/month. It is built to be so real that 24 people who already
use free or paid alternatives will immediately pay for it.

## PART 0 — CONTINUATION PROTOCOL (READ FIRST, EVERY BUILD PASS)

This document is the single source of truth. Any AI coder — or any human —
must be able to open this file and resume the build from exactly where the
previous session stopped, with zero context loss. The rules below are
binding.

### 0.1 How to resume (5 minutes, no questions)

1. Read this Part 0 completely.
2. Find the build log at `docs/BUILD-LOG.md` in the repo (create it if
   missing).
3. Read the last entry. Find the most recent module marker:
   - `[M00] ✅ done` → module complete, move to next module in Part 17 order.
   - `[M00] 🟡 in-progress` → **resume inside that module** at the last
     noted line/instruction. The entry will say exactly where.
   - `[M00] ⚠️ blocked` → read the blocker note. If it is an
     external decision, do NOT proceed past it; surface it. If it is a
     spec gap, resolve it from Part 16 acceptance criteria, note the
     interpretation in the build log, and continue.
4. Never skip a module in Part 17 order. Dependencies are strict.
5. When you complete a module, append its entry to `docs/BUILD-LOG.md`
   before starting the next one.

### 0.2 Build log entry format (mandatory, append-only)

```
[M00] ✅ done · 2026-08-18
  files: Sources/CabinCore/... (+4)
  tests: 12 added, 47 passing
  verified: swift test -c release · xcodebuild build (macOS) · xcodebuild build (iPadOS)
  notes: <one line of anything the next session must know>
```

For `🟡 in-progress` entries, add a final line:

```
  resume-at: Sources/CabinX/Foo.swift:142 · finish FooViewModel.stateMachine
```

### 0.3 Golden rules (never violate)

1. **No platform beyond iPadOS + macOS.** iPhone is cut. watchOS is cut
   (Apple Watch requires an iPhone to pair). Dynamic Island and iPhone Live
   Activities are cut. Everything else must compile and run on iPadOS 17+
   and macOS 14+.
2. **Local-first, offline-first.** The app must be fully functional with
   zero network. Network is an optional enhancement (sync, multiplayer).
3. **Privacy-first.** No telemetry without explicit opt-in. No account
   required. No email or phone. Sign in with Apple only (optional).
4. **Metal, local.** All 3D rendering and material baking is local Metal
   compute. No cloud GPU. No BREV. No server-rendered frames.
5. **The 3D is the product.** Every module must preserve the invariant that
   the 3D cabin, window, and aircraft are the emotional core. If a 2D
   feature and the 3D core ever conflict, the 3D core wins.
6. **Tooling is a product surface.** Build pipelines, bake tools, test
   harnesses, codegen, CI — these are first-class deliverables, not
   afterthoughts.
7. **One-shot per module.** Each module in Part 16 is specified to be
   completable in a single AI session. If a module is too big, split it
   (note the split in the build log) — do not hand-wave.
8. **No secrets.** Never write API keys, tokens, or personal identifiers
   into code or docs. Secrets live in environment/CI keychains only.
9. **"Done" has a definition.** A module is done only when its acceptance
   gates (Part 19) pass, including its tests and its platform builds.

### 0.4 Failure modes and recovery

| Symptom | Recovery |
|---|---|
| Module doesn't compile | Fix compile errors, do not delete code. Log the fix. |
| Tests fail | Tests are the contract. Fix code, not tests (unless test is provably wrong — then log the change). |
| Apple framework unavailable | We target iPadOS 17+ / macOS 14+. Any API must exist at that floor. If not, use the fallback specified in the module. |
| Module scope too large | Split into MXXa/MXXb, update build order, log it. |
| Decision needed from human | Write `⚠️ blocked` entry, stop that module, continue with modules that don't depend on it, list the question at the top of the next handoff. |

## PART 1 — OFFICE-HOURS DESIGN (2026-08-18)

This part records the design session that produced this document. It is the
"why" — read it once, then build from Parts 4–16.

### 1.1 The story (why Cabin exists)

The original Cabin — a year of 3D designs, an inflight entertainment
system, source, and data — was destroyed by corruption. The user rebuilt
a prototype in an 8-day AI sprint (Aug 2026). That prototype reached 212
users; 84 ran the TestFlight build. When the app died, **100+ users asked
unprompted where it went**. 24 users were already paying hundreds of
dollars a year across alternative tools (focus apps, meditation apps,
virtual window apps, "office in the sky" products) and would switch
immediately.

An investor offered **$50k at $4M** — and walked away because the
AI-built product's quality wasn't compelling enough. The user walked away
with the lesson: *AI speed without craft is not enough. Craft, on
schedule, is the whole game.*

Target: **launch summer 2027.** Price: **$20/month.** Platform:
**iPadOS + macOS** (iOS cut). Rendering: **local Metal only.**

### 1.2 Demand reality (Q1)

- 212 prototype users. 84 ran TestFlight.
- 100+ asked unprompted where the app went when it died.
- 24 hot leads: people who pay today for adjacent tools and will pay for
  Cabin. The named example: a 2nd-year PhD math student who does deep
  work at a desk all day and craves the window seat.

### 1.3 Status quo (Q2)

Mixed. Some use free workarounds (wallpapers, meditation timers, white
noise). Some pay (virtual window apps, focus suites, subscription
"ambient office" products). Nobody gets the *combination*: real 787-9
3D window view + cabin presence + full IFE + a serious work/focus system.

### 1.4 Desperate specificity (Q3)

24 named people, each with a concrete pain:

- The math PhD student (named, known) — deep work, desk-bound, hates his
  wall, already tried the free stuff.
- Remote workers on long flights of code.
- People with windowless offices (basement/cube dwellers).
- Frequent flyers between trips who miss the seat.
- Night-shift and early-shift workers who need "daylight" on demand.
- People who use Cabin's competitors and are unhappy (the 24 includes
  these).

### 1.5 Premises (Phase 3 — challenged and held)

1. **Wedge first.** One feature, one persona, one seat. Ship the wedge
   before the plane. (Held.)
2. **Maximal one-shot per module, iterative continuation.** Each module
   must be completable in one AI session, with the continuation protocol
   (Part 0) guaranteeing resumability. (Held, with refinement: a module
   that grows mid-build is split, never abandoned.)
3. **Deliverable = design doc + how-to-proceed.** This document. (Held.)
4. **Local Metal compute, no cloud GPU.** (Held — the user overrode the
   earlier BREV-in-spec idea. Bake locally, render locally, forever.)

### 1.6 Approach (Phase 4)

Chosen: **A) Exhaustive consolidated spec.** One massive spec that
concatenates every repo MD file plus this design, restructured as
independently buildable modules with explicit interfaces, a wedge-first
build order, and the continuation protocol. Any AI coder can pick up the
file and resume mid-module.

### 1.7 What the 24-name list means for the build

The wedge (Part 17) is ordered so that the math PhD student's flow —
**open app → pick a flight → sit in the seat → window + cabin + engine
hum → open Work Mode → focus session with wellness breaks → flight log
stamp** — is the first thing that works end to end. Every module in the
wedge is non-negotiable. Everything else is expansion.

### 1.8 Signals (Phase 4.5)

All six founder signals present: named_users (24), real_problem (the
windowless desk), pushback (user pushed back on scope questions and on
premise #2), domain_expertise (a year of 3D design work, RE'd FocusFlight
assets), taste (quality bar set by the investor rejection), agency
(walked away from $50k rather than ship mediocrity). Closure tier:
**top tier**.

### 1.9 Decisions locked in this session

- D-A: Platforms = iPadOS 17+ and macOS 14+. **iPhone cut.**
- D-B: Local Metal rendering + local Metal baking. No cloud GPU. No BREV.
- D-C: $20/month subscription (StoreKit 2, family share friendly).
- D-D: Premium = AI coach + multiple flight logs. Free = one log, core
  product.
- D-E: Multiplayer stays free.
- D-F: Offline-first; SIWA only for sync/accounts; no email/phone.
- D-G: Launch summer 2027.
- D-H: The 3D core and the tooling are both first-class. No module ships
  without its tooling counterpart (bake tool, test, harness, CI step).
- D-I: This document supersedes all prior docs. Single source of truth.

### 3.3 Why iOS is cut (rationale, binding)

1. The persona sits at a desk with a real screen — a laptop or a
   tablet+stand. iPhone is a second screen at best and a distraction at
   worst.
2. Work Mode, Focus Sessions, IFE browsing, and 3D window views want
   screen area. Everything we build is iPad-class or Mac-class.
3. One less platform means every module's acceptance gates (Part 19)
   run against two builds, not three — which protects the summer 2027
   date and the quality bar.
4. Watch/Dynamic Island features would be the first cut anyway on
   schedule pressure; cutting now removes the debt.

### 3.4 Platform floor (binding)

- Minimum: iPadOS 17.0, macOS 14.0 (Sonoma).
- Swift concurrency (async/await), `@Observable`, SwiftUI, Metal 3,
  StoreKit 2, Sign in with Apple, CloudKit (optional sync), Multipeer
  Connectivity, WidgetKit (iPadOS 17+ / macOS 14+).
- If any API used is newer than the floor, the module must provide the
  fallback. There is no requirement to use the newest APIs.

### PART 4A — AIRCRAFT & CABIN INTERIOR (the 3D core)

#### 4A.1 Aircraft & fuselage

- Base aircraft: Boeing 787-9 Dreamliner.
- Fuselage interior diameter: ~5.49 m (216 in) usable cabin width.
- Floor-to-ceiling height at centerline: ~2.1–2.2 m (82–87 in).
- Cabin cross-section: true circular arc — ceiling curves inward toward
  both walls, walls curve outward from floor. Sidewall-to-ceiling junction
  is a compound curve, NOT a sharp corner.
- Composite fuselage: no rivets, no panel-line seams on the interior.
- Interior cabin length (business zone): 22 rows × ~152 cm pitch ≈
  **33.4 m** (excluding bulkhead fore/aft buffer).

#### 4A.2 Seat layout

- Layout: **1-2-1**, 22 rows, 88 seats total — all Cabin Suite studios
  (branding per 4B.12; geometry unchanged).
- Row lettering: A–D–G–K (A/K window, D/G center pair).
- Every seat: reverse herringbone lie-flat suite with sliding privacy door.
- Pitch: ~152 cm (60 in).
- Seat width (shell): ~76–81 cm (30–32 in) window; center pair slightly
  narrower at shared console.
- Lie-flat bed length: **198 cm (78 in)**.
- Recline: upright → partial → full flat, electric actuator.

#### 4A.3 Seat-specific dimensions & components

- Orientation: reverse herringbone — foot end toward aisle, head end
  faces window.
- Primary shell: ~76 mm thick formed hard shell, matte charcoal/graphite
  with slight warm undertone, Shore 60–70.
- Seat pan: 53 cm wide × 48 cm deep upright; ~58 cm deep reclined;
  wool-blend fabric, ~Pantone 7540 C (warm medium gray) = #7A7872.
- Seat back: 89 cm tall from pan, memory foam core, wool-blend face.
- Lumbar: built in, adjustable via control panel.
- Headrest: detachable side-wing, 30 cm wide × 22 cm tall, wings fold
  inward.
- Armrests: inboard fixed (contains seat control panel); outboard fixed
  at wall ledge. Matte dark navy leather #1C2340.
- Ottoman: 46 × 38 × 38 cm tall, contains companion seatbelt (lap belt
  hidden in cushion gap), upholstery matches pan.
- Privacy door: sliding, flush in hard shell, top/bottom track, fully
  closes suite from aisle.
- Tray table: bifold from forward console wall; deployed **394 mm ×
  597 mm** (15.5 × 23.5 in); faux wood-grain warm oak matte-satin
  laminate (reflectance 10–15%); brushed metal edge trim.
- IFE screen: **24 in** (verified from SFO–LHR footage; some sources say
  27 — 24 is binding), mounted on forward suite wall, flush piano-black
  bezel #0A0A0A (roughness 0.05), swivels ±15°. 4K OLED.
- IFE remote: retractable from inboard console track, matte black, slides
  horizontally.
- Side table: quartzite/faux-marble laminate, white/gray veining on
  off-white base, matte; ~30 × 25 cm.
- Wood-grain trim: warm walnut tone on forward wall, side console, door
  frame; matte lacquer, no gloss.
- Wireless charging pad: flush circle on side console, ~10 cm diameter,
  matte black surround.
- USB-C: 2× centered on side console, brushed aluminum surround. AC: 1×
  universal, lower side console.
- Storage cubby: enclosed drawer under side console, felt-lined (dark
  gray), mirror inside lid. Contains noise-canceling headphones (see
  4C.10 interactivity).
- Seat control panel (inboard armrest): digital touchscreen ~10 × 7 cm,
  backlit ambient white; controls recline, lumbar, headrest, tray,
  lighting; physical buttons ring the touch panel.
- Mood lighting: 8 colors via hidden LED strip at base of side console
  + beneath overhead bin soffit: warm amber, cool white, soft lavender,
  teal, red, deep blue, rose, neutral daylight.

#### 4A.4 Fuselage shell & walls

- Sidewall panels: soft-touch thermoplastic, matte, warm off-white/light
  dove gray **#E8E4DF**; subtle embossed textile weave (~0.3 mm depth).
- Wall curves continuously floor rail → overhead bin attachment; no hard
  corner. Floor-to-bin soffit compound radius: **R120–R140 mm**.
- Aisle floor rail: brushed aluminum T-channel, 3 cm wide, continuous.
- Seat hardpoints: 4× per module, countersunk hex bolts in floor rail,
  concealed by matte plastic cover plate.

#### 4A.5 Overhead bins

- Full-length swing-up door, no center dividers in the suite zone.
- Door surface matches wall #E8E4DF; recessed finger-pull groove in
  brushed aluminum. Interior: matte light gray **#D4D0CB**. No bin
  lighting.
- Bin bottom soffit height from floor: ~1.85–1.90 m.

#### 4A.6 Ceiling

- Compound curved panel following barrel curve, warm white **#F2EFE9**,
  matte, roughness 0.92–0.95.
- Star ceiling: fiber-optic pin points, 0.8–1.2 mm diameter, ~3000 K,
  **200–280 points** per cabin section, irregular star-field pattern,
  invisible at normal viewing distance; appear as glints when cabin
  lights dim. Brightness variation: 20% full, 60% at 70–80%, 20% at
  40–60%. Density bias toward center. Fiber tips recessed 0.5 mm.
- LED cove lighting: continuous strip at ceiling-wall junction both
  sides, warm white 2700–3000 K, diffused through frosted polycarbonate
  lens, soft upwash, no hot spots.

#### 4A.7 Lighting system

- Ambient ceiling LEDs: indirect (bounced via cove channels), 2700–3200 K
  warm white cruise, CRI ≥ 90, no visible fixture.
- Seat mood strips: below overhead bin soffit per suite, 8-color,
  per-seat control, strip ~60–70 cm, milky polycarbonate diffuser
  (3 mm thick, 80% transmission).
- Aisle floor uplighting: blue-white glow at floor rail both sides,
  ~4500 K, very low lumen.
- Reading light: recessed spot in bin soffit above seat, 3000 K,
  400–600 lux at seat level, adjustable within ~20° cone, matte black
  surround.
- Lavatory/galley transition: warm amber ~2400 K.
- Window ambient bleed: natural light dominant daytime fill; windows
  positioned so light hits ceiling/wall curve, not seat pan directly.
- **PBR lighting values (binding):** ceiling ambient strip intensity
  0.35–0.45 (area light); mood strip 0.15–0.25 (strip with diffusion
  envelope); reading spot 0.9–1.2 (spot, 20° half-angle); floor uplight
  0.05–0.08 (area).

#### 4A.8 Windows

- Largest of any commercial aircraft: **280 mm wide × 470 mm tall**
  (11 × 18.5 in).
- Electrochromic glass, **5 stages**: clear → slight blue tint → medium →
  dark → near-opaque deep blue-black (#0A1020). Transition: smooth
  20–30 s gradient center-outward. No mechanical shades.
- Frame: molded composite, off-white #E8E4DF; inner sill depth ~60 mm
  (flat — can hold a phone); window-to-seat-shell edge gap 15–25 cm;
  frame inner reveal ~8 mm, warm gray #D8D3CC.
- Glass PBR: clear stage roughness 0.02, metallic 0, IOR 1.5; Stage 5
  adds emissive absorption mask. 8 mm air gap between panes; micro-
  condensation frost haze possible on clear after dark (45–60 s clear).
- Sill has circular rubber bump-stop, 12 mm diameter, 3 mm proud.

#### 4A.9 Floor / carpet

- Loop-pile carpet, navy-to-midnight blue base **#0D1B3E** with subtle
  geometric diamond/chevron pattern in warm gray **#8A7F74**; pattern
  repeat ~15 × 15 cm; pile ~7 mm.
- Aisle runner: same carpet, tighter weave, aluminum edge strips.
- PBR: roughness 0.97, metallic 0.0, normal amplitude 0.4–0.6,
  displacement < 1 mm.

#### 4A.11 Light diffusion (rendering rule, binding)

The reference 787 cabin (research-derived geometry) uses **entirely
indirect or diffused light** — no
bare bulbs. Diffusion chain:

1. Ceiling cove strips fire upward at wall-ceiling junction; reflected
   light returns as broad shadow-free fill (120° emission cone, no hot
   spots).
2. Mood strips fire downward into the suite through 3 mm milky
   polycarbonate (80% transmission, full LED bead occlusion).
3. Window light enters at high angle, hits ceiling/upper wall first.
4. Star points produce ~0 lux at seat level (decorative only).
5. Net result: **no surface casts a hard shadow** under normal lighting;
   penumbra radius > 10 cm at seat level.

Renderer rule: **no direct lights pointed at geometry** except the
reading spotlight. Use area lights / emissive surfaces bounced off
ceiling and walls as primary illumination.

### PART 4B — WORK MODE, IDLE STATES, AIRCRAFT EXTERIOR, CAMERA, AUDIO, PREFLIGHT, BRAND, GATE-TO-GATE

#### 4B.1 Core design philosophy

The IFE is not a sidebar widget — **it is the app**. Every productivity
tool (timer, task list, focus session, break mode) is presented as if it
were a real airline IFE feature. The passenger never sees a "productivity
app"; they see a seatback screen that happens to contain everything they
need to focus. The screen is always in one of three master states:
**Idle**, **IFE Active**, or **Work Mode Active** (plus Break Mode and
Zen Mode — 4C.10).

#### 4B.2 Idle / ambient states

After **90 seconds** without interaction, the IFE enters an idle state
(not black):

- **Idle A — Relax Loop (default):** cinematic video loops full screen
  (ocean horizon, mountain cloudscape, polar aurora, desert dusk,
  tropical rain); route arc + time-remaining float top-right at ~40%
  opacity; ambient audio matched to visual; mood strip LEDs sync to
  dominant color temperature.
- **Idle B — Moving Map:** 3D globe full screen, no UI overlay; aircraft
  icon pulses slowly; city labels fade in/out; tap anywhere wakes.
- **Idle C — Star Field (night/sleep):** when cabin lighting is dimmest
  and window near-opaque — slow drifting constellations matching ceiling
  fiber optics; brightness drops to ~8%; one line at center: destination
  city + local arrival time (lightest display font).
- **Idle D — Flight Stats Card:** minimal dark card on #0D1B3E: altitude,
  airspeed, outside temp, local destination time, remaining time. Triggers
  when a work session closed within last 5 minutes (cool-down view).
- **Wake trigger:** any touch, remote, or proximity → full home screen,
  300 ms fade.

#### 4B.3 Home screen (active, non-work)

Top status bar: route, duration countdown, local time at destination,
flight phase (Climbing / Cruising / Descending). Hero card (contextual,
rotates): pre-departure ("Your flight to [city] departs in [X] minutes.
Ready to work?"), cruise (session progress or "Start Focus Session" CTA),
pre-landing (arrival card). 4 category tiles (2×2): Work, Entertainment,
Flight, Relax. Bottom nav (persistent): Home · Work · Map · Settings.

#### 4B.4 Work Mode — productivity shell

**Focus session setup (pre-flight check metaphor):** task input ("What

#### 4B.9 Boeing 787-9 exterior — visual & acoustic spec (binding)

**Wing:** wingspan **60 m**; aspect ratio ~10.8–11; sweep ~32.2° at
quarter-chord; supercritical airfoil (upper surface gently convex);
slat seam lines every 2–3 m on leading edge; flap track fairings 4–5

last 1.5–2 m sweeps to ~45–50° and tapers to a point; red port / green

**Wing flex (the defining visual):**
- Ground rest: tip droops 1–2° below level.
- Takeoff rotation: tips already 1–1.5 m above rest at wheels-off; bowing
  visible through window during roll.
- Cruise normal: tips **3–5 m above rest** — gentle upward arch.
- Light turbulence: ±0.5–1 m at 0.3–0.6 Hz, elastic, wave rolls
  root→tip.
- Moderate: ±1.5–3 m; engine pod visibly bobs.
- Severe: ±5–7 m per cycle (operational max ~5.2 m; certified test max
  7.6 m).
- **Flex animation spec (binding):** cubic Bézier root→tip, control at
  ~60% span; root fixed, tip animated; spring stiffness 0.8, damping 0.6;
  ground Y = −1.2% of wingspan; cruise Y = +5.5%; turbulence sine 0.3–0.8
  Hz scaled by intensity; wash-out twist −2–3° root→tip under load.

**Engine — GE GEnx-1B (visual):** nacelle diameter ~2.84 m at fan face;
barrel profile (wide intake, gentle taper, slight flare at nozzle);
rounded elliptical intake lip, no splitter screen; livery #EEE9E2 with
thin brand-blue pinstripe aft of lip; roughness ~0.40; **18 chevrons**
on rear nozzle, ~20 cm deep, curled inward, #C8C3BC; pylon trapezoidal,
matches wing; 18 wide-chord fan blades, dark charcoal, visible stopped →
blur at startup → translucent disk at cruise (3,000–4,000 RPM).

**Engine sound profile (phase by phase, synthesis targets):**
- APU at gate: ~80 Hz fundamental, harmonics to 2 kHz, distant vacuum
  cleaner drone.
- Startup: rising growl from ~60 Hz over 30–45 s, smooth (no bang),
  then idle hiss + tonal hum.
- Taxi: 65–68 dB in cabin, broad hiss 100–400 Hz + occasional whine.
- Takeoff roll: **82–88 dB** — deep rumble 60–100 Hz (felt in seat),
  broadband roar 500 Hz–4 kHz, fan whine overlay 2–6 kHz. "Clean roar,"
  smooth, almost musical.
- Climbout: gear retraction 3–4 thumps (1–2 s each), flap retraction
  shudder, roar fades over 15–25 min.
- Cruise: **56–62 dB** — wind rush 80–150 Hz, GEnx fan hiss 2–3 kHz
  (distant sustained whistle), steady, no pulsing.
- Turbulence: engine unchanged; composite creaks (lower-pitched wood
  settling), wind variation.
- Descent: throttle-to-idle drop, wind rush dominant; speed brakes =
  rough choppy flutter; flap extension whump.
- Approach/landing: gear extension hydraulic clunk + 3 s aero rumble;
  flap rush; go-around spool 4–6 s (rising clean roar).
- Reverse thrust: loudest event, 10–20 s "waterfall" roar, then clunks
  to taxi idle.

**Exterior lighting (binding):** port nav #FF2200, starboard #00CC44,
steady, ~0.6° arc; white strobes ~1 s on / 1 s off (longer than older

#### 4B.10 Camera physics system (binding)

The camera is a **physically simulated skull on a neck in a seat in an
always-moving aircraft** — not a free-fly camera.

- Baseline: eye height 1.72–1.75 m above floor; origin at headrest zone,
  8 cm forward (eyeballs in front of skull); default gaze forward at the
  IFE with **~5° downward tilt**.
- Ground idle/pushback: procedural micro-shake 0.15 mm, 8–12 Hz, all
  axes, below perception threshold.
- Engine startup: damped sine event 0.8 mm, 18–22 Hz, 2.5 s, exponential
  decay, per engine.
- **Takeoff roll:** FOV widens 3–5° (72° → 75–77°) over the 40–50 s
  acceleration, ease-in-out cubic; pitch up 1.5–2.5° (peaks at rotation);
  runway texture shake 1.5–3 mm, 6–15 Hz (frequency drops with speed),
  primarily vertical. **Toggle:** Settings → Motion Effects → Takeoff
  Roll Shake.
- Rotation/climb: nose pitches 10–15°; camera follows at **20–30%** of
  aircraft pitch (neck absorbs the rest), ease-in 3 s. Climb holds 2–3°
  up-pitch.
- **Banking:** camera rolls same direction at **15–20% of bank angle**
  (25° bank → 4–5° roll); 1.5–2 s vestibular lag; window view correct —
  right bank = wing droops, horizon tilts, sky left/ground right.
  **Toggle:** Banking Roll.
- Light turbulence: layered Perlin noise (3 octaves — structured, not
  white), ±1.5–2.5 mm translation, ±0.3–0.5° rotation, 0.2–1.2 Hz +
  4–8 Hz chop overlay; bumpy patches 5–30 s.
- Moderate: ±4–8 mm, ±1–1.5°; single-event "drop" −8–12 mm over 0.4 s,
  return 0.8 s; 0.15–0.8 Hz.
- Severe: ±15–25 mm, ±2.5–4°; drops −20–40 mm / 0.5 s fall / 1.5 s
  recovery; wing flexes ±3–5 m in window; loose objects animate.
  **Toggle:** Turbulence Shake (master off = camera fixed).
- Descent: pitch returns to neutral then −1.5°; sky rises in window.
- Flap extension: damped oscillation 2 mm, 12–16 Hz, 1.5 s, vertical.
- Gear extension: three impulses 3–5 mm, 8 Hz, 0.8 s each, 1–1.5 s apart.
- **Touchdown:** main gear — instant −6–10 mm, bounce +3–4 mm over
  0.3 s, damp 1.5 s; nose gear 2–4 s later −3–5 mm; rollout pitch-down
  1.5–2° over 30 s. **Toggle:** Touchdown Impact.

**Drag-to-look (passenger gaze):** drag anywhere outside the IFE bounding
box to look around; yaw clamped ±60°, pitch +30° / −40°; on release,
camera holds 3.0 s then returns to default gaze with spring
(response 1.2, damping 0.85).

**Three seat positions (physical states):**
1. **Upright** (taxi/takeoff/landing): camera highest, furthest forward.
2. **Lounge/Relax:** pan angles up, backrest 45°; camera lowers and moves
   back ~15 cm; IFE tilts down 10° automatically.
3. **Lie-Flat (Zen Mode):** 180° bed; camera at 80 cm above floor,
   looking slightly upward.

#### 4C.15 Multi-person flights (serverless, free)

#### 4C.16 Scale, performance & background intelligence

**Adaptive performance tiers (auto-detected < 200 ms on launch):**

## 5.2 State model

Single `@Observable` `CabinStore` is the source of truth. Three state groups:

1. **Preflight** — `phase` (onboarding → route → seat → ticket → checkin), `routeDraft*` (bidirectionally bound to globe pins and flight-time scrubber), `seatLayout` (deterministic from route seed), `issuedTicket`.
2. **Cabin / IFE** — `flightPhase` (gate→taxi→takeoff→climb→cruise→descent→approach→landing→taxiIn), `masterMode` (idle / ifeActive / workActive / breakMode / zen), `idleState` rotation (relax loop → moving map → star field → stats card after idle timeout), `ifeTab`.
3. **Work session** — `workSession` (phase: work / break / longBreak / ended), wellness score, notes/checklist, interval bookkeeping, force-break.

`CabinStore.tick()` runs at 20 Hz and drives flight clock, idle detection, wellness decay, break auto-end, camera physics, and render tuning.

**Multiwindow policy (binding):** one primary window owns the Metal view and audio; secondary windows route IFE-only via `SceneStorage` per scene. `CabinStore` remains a global singleton with window-scoped IFE routing (PORT-SPIKE risk #3, resolved).

## 5.3 Metal pipeline (the 3D heart — M06/M07/M08)

- `MetalSceneView` hosts one `MTKView` per scene (globe, cabin, window), each with a `Renderer`. The representable already exists in **both** NSViewRepresentable (macOS) and UIViewRepresentable (iPadOS) variants (frozen API contract) — the port seam is already cut.
- `Renderer` renders into an **offscreen texture at a configurable internal resolution** (the battery lever), then a **post pass** applies brightness / warmth / color-correction / dim to the drawable.
- Scenes are **procedural**: `MeshFactory` builds spheres, extruded rings, lathes, tubes, boxes. `TextureBaker` bakes land (Natural Earth), stars, carpet, leather, wood, quartzite, wall, ceiling, star ceiling, clouds to GPU textures at launch.
- Shaders are embedded MSL compiled at runtime (`ShaderSource.swift`): PBR-ish BRDF with hemisphere fill + up to 8 point lights; modes for unlit starfield, atmosphere rim, arc, pin billboard, globe (day/night emissive), sky. Wing flex is a quadratic vertex bend driven by spec-exact flex values per-draw.
- **Lighting follows the diffusion chain (binding):** no direct lights except the reading spotlight; cove upwash, aisle uplights, mood strips, star ceiling are emissive + point fill. Runtime samples pre-baked lightmaps only (D-8); indirect lighting is baked on the dev Mac's Apple GPU via SeatBakery (Metal compute) at build time.
- Post-pipeline: sRGB framebuffer, ACES-style tone map, bloom, MSAA (high tier only).
- **LOD tiers:** selected full-poly, ±2 rows medium, everything else silhouette — locked by `CabinSceneTests`.

## 5.4 Camera physics (`CameraPhysics`)

Vestibular model: takeoff FOV zoom (72°→76.5°), seat-back press (2.2°), runway shake (1.5–3 mm @ 6–15 Hz), lagged partial banking roll (18% of bank, 1.7 s time constant), layered-Perlin turbulence with drop events, gear/flap impulses (3 thumps, 1.2 s apart), touchdown impact, APU microshake (true 8–12 Hz). Every effect has a Settings toggle; `reduceAllMotion` zeroes the whole output. All constants live in `MotionSpec.swift`, cited to CabinSpec Part 4, locked by `MotionSpecTests` and `SoundPositionTests` (audio analogue).

## 5.5 Audio (`SpatialAudioEngine`)

`AVAudioEngine` + `AVAudioEnvironmentNode`. Procedural `AVAudioSourceNode`s sit at the spec's physical positions (engines ±7 m below / 11 m aft, wind at window ~50 cm from ear, HVAC overhead at 2.1 m, IFE 0.75 m forward, PA overhead-forward, pax murmur at ±3.5 m, galley chime ~6 m aft at half volume) and are rendered with HRTF over headphones / equal-power panning over speakers (Settings → Audio Output picker; `renderingAlgorithm(for:)` pure + unit-tested). Per-phase engine profile shapes gains; bundled soundscapes and synthesized chimes (classic / soft bell / Tibetan bowl) route through the same node. Listener = the vestibular camera position, wired per tick in `CabinStore.tick()`.

## 5.6 Accessibility pipeline

`CabinStore.announce(_:subtitle:)` is the single funnel for flight / work / meal announcements; renders a 5 s closed-caption bar when captions on; speaks via `AccessibilityEngine` (AVSpeechSynthesizer) when Speak Screen on; DND silences only audible TTS. Zoom (⌘± runtime × persisted Text Size, 1.6× effective cap); High Contrast is a real post-shader pass; both Reduce Motion toggles feed camera physics via `syncMotionSettings()`. Haptics via `HapticProvider` (NSHapticFeedbackManager on macOS / CoreHaptics on iPadOS), gated by persisted Haptics setting. Per-platform AX gate before each platform ships (SPEC-DEVIATIONS §6).

## 5.7 Persistence

`PersistenceEngine` writes JSON snapshots to Application Support (settings, trips, membership, world cards, sessions, wellness, phase, active work session). Envelope carries `schemaVersion` + migration runner (legacy v0 files migrate; no silent failure). Everything survives relaunch; `resetEverything()` clears. iCloud sync design decision (record mirror) lands in Phase 2 with
multiplayer work; the shipping sync work is M31 (Phase 4).

# Part 6 — Assumptions & Known Gaps (consolidated & adapted)

## 6.1 Platform & toolchain

- **iPadOS 17.0+ / macOS 14.0+ (Sonoma), Apple Silicon + A/M-series.** (Supersedes ASSUMPTIONS.md's "macOS 15+ only": the platform decision D-A adds iPadOS 17+, keeps Apple Silicon as the render floor with an adaptive 2D fallback for weaker iPads — M36.)

- **Swift Package + XcodeGen, not a raw Xcode project.** `Package.swift` builds runnable targets (`swift run Cabin`, `swift run SeatBakery`); `project.yml` generates the two app projects (iPadOS; macOS) with entitlements, resources, signing.

## 6.2 Content that is mocked (schema-real, content-synthetic)

- **Movies / TV / audio catalog** — real UI + data models; titles without licensed assets are original, license-free stand-ins. Bundled local assets (`cloud1.mp4`, `parisSatelliteDemo.mp4`, `.m4a` beds) play through AVPlayer with real play/pause/elapsed/completion cleanup and battery-aware pause/resume. Items without a local asset are explicitly labeled unavailable offline — never simulated playback.
- **Live TV channels** — real channel guide UI, synthetic feed. **Weather at destination** — route seed + latitude derived, no live API. **Control Tower data** (wind/vis/QNH/departures) — seed-derived, real UI.

## 6.3 Rendering choices

- **Globe** — procedural sphere, Natural Earth land polygons (public domain) baked to 4096×2048 at launch, day/night emissive pass, atmosphere rim, starfield skybox sharing the globe's yaw. Spec's "slippy-tile globe with LOD cross-dissolve" delivered as single high-res equirectangular bake + mip chains — tile streaming judged unnecessary at 4096 px and would add network/battery cost. (If a future build needs true globe zoom beyond this, revisit M06 — recorded, not deferred silently.)
- **787-9 plan silhouette** (`Boeing787Plan`) — spec-derived: 32° quarter-chord sweep, 47° raked tip over outboard ~6% half-span, 0.22 tip taper, flap-track fairings (4 per wing), GEnx nacelles at 40% span, swept stabilizers, six depth layers — locked by `PreflightGeometryTests`.
- **Cabin interior** — fully procedural, test-locked (`CabinSceneTests`): 5.49 m barrel, 2.1–2.2 m floor-to-ceiling, 22 × 1.52 m pitch = 33.44 m, tray 394 × 597 mm, EC windows 280 × 470 mm, 1-2-1 seat-X symmetry, three LOD tiers.
- **Battery-first rendering** — on-demand redraws when static, occlusion + inactive pause (Metal scenes *and* Relax Loop AVPlayer), internal resolution scaling per graphics preset, frame limiter; the spec's own battery/hr figures define the presets.

## 6.4 Audio choices

- **Engine sounds synthesized live** (filtered noise + oscillator banks, one-pole smoothing, phase-shaped gains) — no licensed recordings; every source positioned via `AVAudioEnvironmentNode` HRTF at spec meter positions.
- **Startup spool** — Engine 1 spools at pushback, engine 2 at takeoff: rising fan whine (N1 exponential curve, faded 8→10 s, ceiling 0.09; 600→2200 Hz ramp), phase-integrated for continuous pitch; armed only by real triggers; `resetTransients()` clears stale state.
- **Reverse thrust** — scheduled ~2 s after touchdown (during rollout, not taxi): one-shot roar = broadband noise + 31 Hz rumble + 2.9 kHz spooled-whine, 5 s envelope peaking 1.2 s after engagement (~3.2 s post-touchdown); lock-guarded pending flag consumed by audio thread; cleared on go-around and reset.
- **PA announcements** — PA source profile + chimes; recorded voice deferred (TTS synthesis of PA is a Phase 5 candidate, §5.5).

## 6.5 Motion & camera values (fidelity rule #3)

All spec-locked constants in `MotionSpec.swift`, cited to CabinSpec Part 4, locked by `MotionSpecTests`. Audit-fixed violations (binding):
- Flex oscillation band now 0.3–0.8 Hz (was 0.08–0.22 Hz): light 0.55 / moderate 0.70 / severe 0.50 Hz; amplitudes light ±0.75 m / moderate ±1.8 m / severe ±5.2 m.
- Operational clamp: cruise flex (3.3 m) + severe oscillation (5.2 m) clamped at operational max 5.2 m; certified one-time test max 7.6 m never reached.
- Flex magnitudes: ground −0.72 m (−1.2% × 60 m span), climbout +2.4 m (+4%), cruise +3.3 m (+5.5%); descent "slowly flattens"; approach "near-ground flex".
- Banking 0.18 ∈ [0.15, 0.20], lag 1.7 s ∈ [1.5, 2.0]; gear 3 thumps 1.2 s apart ∈ [1, 2] s; APU microshake true 8–12 Hz (was ~1.5 Hz).
- Takeoff FOV 72→76.5°, seat-back press 2.2°, runway shake 1.5–3 mm @ 6–15 Hz — not numeric in spec; shipped values documented here and test-locked.

## 6.6 Sound source positions (directive §6)

`SoundPositions.swift` table, locked by `SoundPositionTests`: engines ±7 m lateral / 7 m below / 11 m aft (spec: ~7 m below, 10–12 m aft); airframe hiss at window (~50 cm); HVAC overhead at ceiling (2.1 m; spec's "60–80 cm overhead" assumes lower seated ear — with 1.72 m listener the ceiling caps overhead reach ~0.5 m); IFE 0.75 m forward; seat motor below/behind at pan level; PA overhead-forward; pax beds ±3.5 m (spec: 3–6 m); galley repeat of crew-call chime ~6 m aft at half volume. ## 9.2 The material grammar (the shared "expensive" code — all twelve)

- **Real stone at hand-touch surfaces** (quartzite, marble, Corian) — stone reads hotel, plastic reads airplane.
- **Wool, always wool** — breathability, acoustics, "the good hotel."
- **Open-pore, aging wood** — patina over gloss = quiet luxury's definition of richness.
- **Soft-touch/suede interiors** — the "don't touch" surface you're invited to touch.
- **One metallic thread** — warm metal (champagne/rose gold/brass), never raw silver.
- **Frosted/translucent light carriers** — light is never a bare bulb; always carried by a material.
- **Textured acoustic panels** — pattern + sound absorption in one gesture.
- **CMF system rule:** vertical brightness gradient (dark floor → warm ceiling); one jewelry accent color; texture variation where color can't vary.

## 9.3 The light-design model (circadian science, abstracted)

Industry standard is now flight-phase scene systems (Delta's phase scripts; Qantas's 12-scene melanopic model developed with the University of Sydney; Bombardier Soleil's work/sleep presets). Our five stages + porcelain gate (binding, from SPEC-DEVIATIONS §6 + research):

| Stage | Phase | CCT / intensity | Scenery |
|---|---|---|---|
| Welcome | session start | ~3500 K, 60% | Porcelain cove rises; window oval glows |
| Climb / Work | active focus | **4000 K**, 100% | Blue-enriched, high melanopic; gold only at the reading point |
| Sunset / Break | break | **2800 K**, 40% | Candlelit warmth; gold pools; teal at the window |
| Night Crossing / Zen | Zen | **2200 K ember + 5% drive**, <10% | Star ceiling; only the window oval + one reading lamp lit |
| Approach / Landing | session end | 2800→4000 K over 90 s | Sunrise sweep front-to-rear; landing gold CTA; blinds up |

**Rule:** every mode transition passes through the porcelain 3500 K gate — never cut between modes directly. Suites-level light is a personal circadian clock ("choose the time zone you want to be on").

## 9.4 Ritual library — 5 signature moments (light + sound + motion)

1. **The Welcome** (session start) — cove to 3500 K over 2.4 s; window oval ignites; cabin-hum bed fades up; one soft chime; PA (TTS, calm): "Your suite is ready"; glass panel slides closed (springPanel 0.42/0.86); DND placard flips on.

# Part 12 — Baking (SeatBakery artifact pipeline)

> Source: `BAKING.md` (superseded by this part) + SPEC-DEVIATIONS §1 + BAKING output facts. SeatBakery is the **tooling first-class citizen (D-14)** — an offline artifact generator, part of the dev workflow, never a runtime dependency.

## 12.1 What it emits

`SeatBakery` uses the same named material surfaces as `CabinMaterials` and emits **14 material surfaces × 7 map channels** = **98 maps**:
albedo · normal · roughness · ambient occlusion · displacement · emissive · baked indirect-light fallback.

**CPU path is deterministic** (the contract for CI and smoke tests). **`--gpu` path** uses sequential Metal compute on the system GPU (Apple Silicon), dispatching procedural map generation through compute, reading back RGBA, packing P6 PPM, writing a checksummed `bake-manifest.json`. `--samples` / `--diffuse-bounces` perform deterministic jittered accumulation **only** for the `bakedLight` map; the manifest records them separately from legacy single-pass fields. It is GPU-accelerated, not 100% utilization: CPU readback, checksum, and disk I/O necessarily interrupt compute.

## 12.2 Commands (binding)

```sh
# CPU smoke bake (CI): deterministic
swift run SeatBakery --output /tmp/cabin-bake --resolution 256

# Metal GPU bake on the dev Mac: full production tier
swift run SeatBakery --gpu --output .build/cabin-bake-gpu-4096 --resolution 4096 \
  --samples 8 --diffuse-bounces 4 --force

# Runtime opt-in (dev builds): serve baked artifacts to the app
CABIN_BAKE_DIRECTORY="$PWD/.build/cabin-bake-gpu-4096" swift run Cabin

# Bounded developer overrides (battery/memory safety)
CABIN_ARTIFACT_MAX_RESOLUTION=4096 \
CABIN_ARTIFACT_CACHE_BUDGET_MB=1024 \
CABIN_BAKE_DIRECTORY="$PWD/.build/cabin-bake-gpu-4096" swift run Cabin
```

## 12.3 Runtime contract (binding)

- Runtime artifact loading **defaults to maps up to 1024×1024 and a 256 MB resident artifact budget** — battery/memory safety is the default, not the exception.
- Env overrides are bounded and opt-in (`CABIN_ARTIFACT_MAX_RESOLUTION`, `CABIN_ARTIFACT_CACHE_BUDGET_MB`).
- PPM chosen so artifacts are inspectable with zero image dependencies in the package.
- `.build/cabin-bake-gpu-4096` is gitignored; the **manifest is the source of truth** for what a bake contains (checksums per map, samples, bounces, production target recorded).

## 12.4 Honesty bar (binding, from BAKING.md)

`metal-gpu-local` means GPU-generated procedural PBR maps with an optional material-field indirect accumulation. It does **not** claim that geometry lightmaps, Cycles GI, ray-traced reflections/refraction, subsurface scattering, volumetrics, or the requested 32K / 8,192-sample / 32-bounce production bake were produced. The manifest records the CabinSpec production target (32K primary maps, 8,192 samples, 32 diffuse/specular/transmission bounces) **separately** — reference-only per Part 7 §7.1.

## 12.5 Tooling gates (D-14)

- Phase 0 exit: bake pipeline produces a sample suite lightmap (suite-area irradiance + reflection probe for IFE/quartzite glow + soft contact shadow for the reading spot).
- CI: CPU smoke bake runs per-PR; manifest checksum diffed; `--gpu` bake runs nightly on the dev Mac.
- Phase 3: full 98-map 4096² GPU bake checked into the artifact pipeline; runtime default tiers verified against the 256 MB budget.
- Phase 5: baked indirect lighting is the fidelity gate (§7.1 "Real indirect lighting" bar).

# Part 13 — Communications / Serverless Contract

> Source: `SERVERLESS.md` (superseded by this part; reconciled with Part 7 §7.3). Cabin ships with a complete offline transport. **No account, backend, network, or credentials are required for the native app** (D-10).

## 13.1 LocalCommsTransport (the production-safe default)

`LocalCommsTransport` persists thread snapshots in Application Support as `comms.json`. Supports cabin, crew, and companion threads; queued/delivered/read/failed states; works in airplane mode. This is the **default** and the only transport in the shipping critical path.

## 13.2 HTTPSCommsTransport (optional, provider-neutral)

Configure a base URL in a host application and expose:

- **`POST /messages`** — request and response are `CommsMessage` JSON; a successful response must return the same message with its authoritative delivery state (`delivered` | `read`) and timestamp.
- **`GET /threads`** — response is an array of `CommsThread` JSON; the server owns canonical thread ordering and may return read states for the current device/user.

A minimal serverless handler can be deployed to any HTTPS function platform (Vercel Functions, Cloudflare Workers, AWS Lambda/API Gateway, or a custom service) **without changing the Cabin client**. Authentication, rate limiting, retention, and encryption belong at that deployment boundary; the native app does not invent credentials or silently upload local passport data.

## 13.3 Binding decisions

- The current package includes **no provider account or deployment secret** — the local transport remains the production-safe default (Part 7 §7.3: serverless removed from the multiplayer critical path).
- To make remote comms live later: inject an `HTTPSCommsTransport(baseURL:)` from the host app and replace the store's transport wiring in the app target. That wiring is the only integration point.
- Multiplayer itself (rooms, presence, text, voice) is **CloudKit + Multipeer**, not serverless (§7.3) — the serverless contract is a separate, optional relay surface.

# Part 20 — The Assignment (lineage & decision record)

## 20.1 Origin

The /office-hours skill (startup mode) produced this design in Phase 5 of its workflow. The assignment was to produce a single consolidated rebuild spec for **Cabin** — "the focus-ritual airline: every focus session is a flight" — from the 3,098-line master spec (`CabinSpec.md`), the frozen API contract, the reviewed 8-month plan, and the accumulated design/brand/bake/seat docs, resolving all conflicts into one binding document.

## 20.2 The six forcing questions (startup mode) & answers

1. **Demand reality** — Who is the passenger? The focus-ritual user: a knowledge worker who wants work, rest, and Zen wrapped in a luxury ritual, offline, on their own devices. Not a frequent flyer — a frequent *focuser*.
2. **Status quo** — What exists today? Focus timers (Pomodoro apps), ambient apps (Endel), white-noise apps, and a RE'd competitor (FocusFlight). None marry a full 3D cabin + IFE + work ritual + wellness + multiplayer in one offline product.
3. **Desperate specificity** — What is the narrowest wedge? The preflight-to-landing ritual: pick a route, pick a suite, board, work, land. The flight *is* the session — the ritual IS the differentiator, and the 3D cabin makes it real.
4. **Observation** — What did we observe in the research? The world's best cabins sell solitude, materiality, and light-as-science; luxury = anticipation + restraint; the rituals (first pour, turndown, stamp) are the memory points.
5. **Future-fit** — What does this become? A habit-forming focus ritual with a collectible passport, social presence (multiplayer free), and an AI coach; a launchpad for the fictional airline world.
6. **Narrowest wedge** — v1 = iPadOS + macOS, offline-first, one 787-9 cabin, 22 rows, the full ritual, premium = coach + multiple logs.

## 20.3 Approaches considered

- **A (chosen):** Full single-team rebuild in 8 months — entire 3,098-line spec in scope for two platforms, modular M00–M45, crews + CI + tooling. Everything above, locked by binding bars.
- **B:** Minimal v1 (timer + window + log) — rejected: violates D-2 (no cut lines) and the 3D-first directive.
- **C:** Staged platform expansion (macOS now, iPadOS later) — partially adopted: macOS ships first, but iPadOS is in the same 8-month horizon (D-A), and the adaptive shell starts in Phase 1, not Phase 3.
